# Commercial and Claim Boundaries

## What Dharma can sell initially

> Connect local coding agents across a company, analyze their real trajectories, identify repeated workflow failures, dispatch bounded tasks, and automatically distribute verified Skill updates across providers.

## Strong initial value statements

- Keep developers on their preferred coding agents while giving the company one improvement loop.
- Turn local trajectories into organization-wide failure intelligence.
- Deliver a verified Skill remediation to every affected agent instead of leaving a PDF or dashboard finding.
- Send bounded work to local agents without exposing an inbound remote shell.
- Use customer provider accounts for local execution and charge Dharma model tokens only when Dharma performs semantic analysis or managed execution.
- Preserve exact installation and rollback evidence for every Skill release.

## Claims requiring proof before use

Do not claim these until the stated threshold is met.

### Universal provider independence

Required proof: equivalent evidence, task, Skill, authority, and rollback behavior across at least two materially different providers and operating systems.

### Automatic remediation

Required proof: multiple organization-approved Skill remediations pass held-out validation, release, canary, installation, and post-rollout re-verification without unacceptable regression.

### Organization-wide improvement

Required proof: measured reduction in recurrence, correction burden, recovery time, or another agreed outcome after rollout.

### Production self-healing

Required proof: a production failure is diagnosed, a bounded remediation is generated, released under authority, and the live workflow is re-verified. Prefer not to use this phrase.

### Integrity-contract compiler

Do not use as a current claim. The first system proposes rubrics and candidate contracts. Authority requires validation and approval.

### Complete trajectory capture

Do not use when evidence is reduced, provider fields are missing, or upload policy excludes content. Report exact coverage.

### Secret-safe

Do not promise perfect secret elimination. State that local filtering and policy reduce exposure and that incidents remain possible.

## BidStitch-style evidence boundary

An illustrative production-path evaluation may show that structured state improves a handoff. It does not establish that the historical customer incident occurred, that a code repair was deployed, or that revenue was recovered unless customer-production evidence proves those facts.

## Customer-facing package name

Recommended:

**Dharma Agent Fabric Pilot**

Subtitle:

> Organization-wide trajectory intelligence, bounded task orchestration, and verified Skill remediation for local coding agents.

## Public open-source positioning

> An open local relay for connecting coding-agent trajectories, tasks, and signed Skills to an organization control plane.

## Investor positioning

> Every coding agent learns locally. Dharma turns that local evidence into a company-wide improvement loop: real trajectories go up, verified Skill remediations come back, and every affected agent updates automatically.

## Differentiation from Better Harness

Better Harness improves one project's local agent work loop and produces evidence-backed reports. Dharma Agent Fabric adds continuous organization-wide synchronization, remote tasks, A2A communication, multi-tenant evaluation, GitHub-governed Skill source, automatic signed rollout, billing, and managed execution.

## Differentiation from observability

Observability records what happened. Dharma connects the finding to a bounded Skill change, held-out proof, rollout, installation receipt, rollback, and later outcome evidence.

## Differentiation from remote coding-agent platforms

Remote coding-agent platforms run work in their environment. Dharma can use those environments, but also governs agents already running on developer machines under existing provider subscriptions.
