# Agy 1.1.13 Capability Evidence

## Scope

This record covers the public `agy` 1.1.13 CLI surface tested on 2026-08-17.
It is capability evidence, not a claim about undocumented files or future Agy
versions. The probe used an isolated `HOME` and removed it after completion.

## Public CLI surface

`agy --help` exposes non-interactive `--print`, JSON output, `--sandbox`, plan
mode, a log file, project/conversation selectors, and timeout controls. It also
exposes `--dangerously-skip-permissions`; Agent Fabric must never use that flag.

`agy plugin --help` exposes `validate`, `install`, `list`, `enable`, `disable`,
and `uninstall`. It does not expose:

- path-scoped write authority or a registered-command allowlist;
- signed task or action-decision envelope input;
- action digest, idempotency key, effect acknowledgement, or signed receipt output;
- an exact active Skill content hash, commit, version, or activation revision;
- transactional plugin activation or a rollback receipt.

## Isolated lifecycle probe

The following public command sequence succeeded for a minimal local plugin:

```text
agy plugin validate <plugin-directory>
agy plugin install <plugin-directory>
agy plugin list
agy plugin enable dharma-capability-probe
agy plugin disable dharma-capability-probe
agy plugin uninstall dharma-capability-probe
```

The observed behavior limits the claim that can be made:

- install copied the plugin into `~/.gemini/config/plugins` under the isolated
  home rather than executing it from Agent Fabric's staged source;
- `AGY_CONFIG_DIR` did not relocate that registry;
- `plugin list` returned the same name/components record before and after
  enable or disable, so it did not attest activation state or content identity;
- uninstall removed the import but left the separate enabled-state entry.

These observed paths are not a supported integration API. Agent Fabric must not
build receipt or rollback semantics by mutating them directly.

## Advertised result

| Capability | Agy 1.1.13 | Basis |
| --- | --- | --- |
| Evidence capture | `partial` | Workspace-qualified history and native transcript records are observable; usage and complete coverage are not. |
| Task execution | `partial` | Only isolated, sandboxed plan-mode reads without commands or writes are allowed. |
| Action-decision receiver/receipts | `unavailable` | Consequential effects cannot be bounded or acknowledged through the public CLI. |
| Skill install | `partial` | Public install commands exist, but they do not attest the exact active signed bundle. |
| Activation | `unavailable` | No public output binds enabled state to an exact bundle hash or session. |
| Rollback | `unavailable` | Disable, uninstall, and reinstall are not an atomic, attestable rollback protocol. |

GA promotion requires a supported Agy interface that binds execution authority
to paths and commands, returns effect acknowledgements keyed by action digest and
idempotency key, and attests exact Skill activation and rollback identity. Until
then, the relay fails closed for signed action decisions and automatic Agy Skill
installation.
