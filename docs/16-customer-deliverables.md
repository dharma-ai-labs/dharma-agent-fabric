# Customer Deliverables

## Continuous product surfaces

The customer console provides:

- connected developers and devices;
- registered repositories;
- provider capability matrix;
- trajectory coverage and upload policy;
- current organization Skills;
- task and A2A activity;
- evaluation runs;
- failure families;
- remediation proposals;
- release and rollout status;
- usage, model cost, and hard caps;
- audit and disclosure receipts.

## Evaluation deliverable

A bounded evaluation produces:

- workflow and task-episode definition;
- evidence and privacy boundary;
- provider and repository coverage;
- custom evaluation contract;
- deterministic verifier set;
- judge configuration and cost;
- baseline findings;
- failure atlas;
- remediation backlog;
- held-out suite;
- management scorecard;
- raw machine-readable results.

## Remediation deliverable

A remediation cycle produces:

- named failure family;
- affected cohorts;
- smallest responsible layer;
- proposed Skill or policy change;
- GitHub pull request;
- historical replay;
- matched retest;
- held-out evaluation;
- regression analysis;
- signed release candidate;
- canary and rollout evidence;
- installation receipts;
- rollback manifest;
- post-rollout outcome delta.

## Executive scorecard

The executive artifact answers:

1. What repeatedly failed?
2. What customer or engineering consequence did it create?
3. Which agents, providers, repositories, or teams were affected?
4. What did Dharma change?
5. What evidence showed the change worked or did not work?
6. Which devices installed it?
7. Did recurrence, recovery time, human burden, or customer outcome change?
8. What remains unsafe, unsupported, or unknown?
9. How is the change rolled back?
10. What should the organization do next?

## Failure Atlas interface

Each failure family displays:

- signature and examples;
- cause class and confidence;
- detection logic;
- affected workflows;
- severity;
- recurrence trend;
- accepted remediation;
- applicability limits;
- release history;
- outcome evidence;
- disclosure and reuse policy.

## Organization Skill registry

Each Skill displays:

- purpose;
- authoring branch;
- current release;
- source commit;
- risk class;
- providers and repositories targeted;
- eval and held-out result;
- devices installed;
- activation mode;
- rollback version;
- observed post-release effect.

## API export

Customers can export:

- evaluation contracts;
- deterministic verifiers;
- failure atlas entries;
- trajectory references within their rights;
- Skill source and release manifests;
- installation receipts;
- billing events;
- audit records;
- remediation packages.

Exports must preserve provenance, schema version, and evidence boundaries.
