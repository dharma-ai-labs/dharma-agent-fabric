# Evaluation and Remediation

## Create evaluation

Name the workflow, task family, failure family or discovery objective, repositories, providers, evidence window, hidden truth, deterministic checks, semantic judge, cost cap, and expected decision.

## Interpret results

Separate:

- deterministic evidence;
- semantic judgment;
- missing evidence;
- agent, handoff, environment, mixed, or unresolved cause;
- comparative behavior;
- causal claims;
- staged versus customer-production evidence.

## Propose remediation

A remediation proposal must identify the smallest responsible Skill, rule, hook, policy, prompt, validation command, routing logic, or authorized code owner.

Do not call a generated change verified until historical, matched, held-out, regression, release, and post-release requirements appropriate to its risk class pass.
