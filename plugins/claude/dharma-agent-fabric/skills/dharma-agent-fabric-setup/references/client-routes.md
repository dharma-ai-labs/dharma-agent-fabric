# Client Routes

Select only the route requested and actually qualified for the current release.

| Route | What must be observed | What it does not establish |
| --- | --- | --- |
| Connected OAuth MCP | Current human identity, exact organization, active membership and permission-qualified read/tool results | Device enrollment, persistent relay, arbitrary shell access or continuation of a desktop conversation |
| Guided interactive CLI | Bare `dharma` explicitly supported by the qualified release; normal intended-account browser flow; official protected storage; final device receipt | Provider sign-in, shared-package readiness, an enforced task or restart proof |
| Portal source-connected agent | Exact pinned prompt and recipient/repository/policy; genuine supported harness; matching browser approval; final original-process receipt | Knowledge-only joining, another repository or arbitrary provider support |
| Existing knowledge-only join | Existing selected binding and signed release; effective recipient role; a separately qualified join/setup contract; activation receipt | Source ownership, source collection, code writes or a fresh source candidate |
| Existing enrolled recovery | Same device, protected identity, original binding and cause-specific released recovery contract | Permission to replace keys, replay grants, reset retry counters or restart another owner's service |

The four provider IDs accepted by current CLI command parsing are `codex`,
`claude`, `agy` and `hermes`. Parsing or installed asset discovery is not live
support for every table row. Use the actual provider capability receipt, and
label unqualified stages honestly. Do not spoof one provider as another.

Grok is not a CLI provider ID. On Grok, use only the Connected OAuth MCP route:

- Grok CLI (Grok Build): `grok plugin marketplace add dharma-ai-labs/dharma-agent-fabric`,
  then `grok plugin install dharma-agent-fabric --trust`, then sign in through `/mcps`
  (select `dharma-agent-fabric`, press `i`).
- Grok Bot or grok.com: a custom connector for `https://mcp.dharma-ai.io/mcp`, authenticated
  with the intended Dharma account.

Fabric tools require an explicit `organizationId`; no tool enumerates memberships. Ask the
user for the ID from their organization workspace at `https://www.dharma-ai.io/portal`, then
confirm membership with `fabric_get_identity` for that ID. A Grok connection does not
establish device enrollment, a relay or any CLI route row above.

For the selected Linux named-Codex route, the official setup entry opens its
owned named setup session; it does not attach to an arbitrary existing desktop
chat. The initial trusted setup boundary is separate from subsequent coding and
read-only peer turns. WSL and an isolated container can share a host/kernel;
disclose that topology instead of describing them as independent hardware.

If shell execution is unavailable, use only the existing supported connected-app
flow and capabilities. Do not claim that an OAuth control-plane read is a
substitute for an enrolled native client. Report the exact required private
human authentication or approved client prerequisite without handling credentials.

## Qualification at This Artifact Revision

The recorded CLI211 source does **not** implement a bare interactive guided entry:
`run([])` reaches usage failure. First enrollment through `login` currently
requires an explicit organization ID. Therefore the guided-entry row is blocked
on this revision; do not execute it as though it existed or publish this skill as
a proven full setup solution.

The source has an existing `joinExistingRepository` knowledge-only mechanism,
using an isolated managed knowledge workspace and a selected existing binding.
That is not proof that the current source-only portal setup-reference contract
supports knowledge-only issuance, nor that a fresh recipient has completed it.

Actual non-Codex guide-only use, repository-independent recipient setup, the
automatic per-worker 100-boundary loop and complete factory acceptance remain
separate release gates. Consult the external hash-bound qualification record;
this skill deliberately supplies no success receipts or executable fallback.
